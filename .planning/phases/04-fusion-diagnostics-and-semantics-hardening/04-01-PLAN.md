<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller→fusion contract | Untrusted caller-constructed mappings and numeric diagnostics enter frozen public dataclasses. |
| fusion result→artifact consumer | Machine-readable diagnostics may be serialized by downstream tools that assume scalar JSON-ready values are stable and truthful. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | `FusionProvenanceSummary`, `FusionConflictSummary`, `FusionResult.diagnostics` | mitigate | Copy input mappings with `dict(...)` before wrapping in `MappingProxyType`; test caller-side mutation does not change summaries. |
| T-04-02 | Spoofing / Repudiation | `FusionUncertaintySummary.model_label` | mitigate | Require explicit non-blank label; Plan 01 defaults are explicitly compatibility-only, and Plan 02 uses exact `preserved_not_optimized` label in typed and flat diagnostics so reference fusion cannot masquerade as Gaussian optimization. |
| T-04-03 | Denial of Service / Tampering | uncertainty numeric fields | mitigate | Reject non-finite, negative, and max-less-than-min covariance diagonal stats in dataclass validation. |
| T-04-04 | Information Disclosure | `FusionResult.diagnostics` | mitigate | Keep `FusionMetricValue` scalar; do not add raw splat arrays, full per-output-splat lineage, or stable splat IDs to flat diagnostics. |
| T-04-SC | Tampering | package installs | accept | No package-manager install tasks exist in this plan; Phase 04 uses stdlib dataclasses/types/typing and existing pytest workflow only. |
</threat_model>
