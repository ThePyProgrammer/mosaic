<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User code to BackendRegistry.register | Untrusted backend descriptors enter the registry namespace and can spoof existing names if duplicates are not rejected. |
| Availability check to Python environment | Declarative dependency names are checked against the local interpreter without importing optional backend modules. |
| Descriptor metadata to downstream tests/evaluation | Static metadata is consumed as trusted JSON-ready values and must not mutate after registration. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Elevation of Privilege / Denial of Service | `BackendDescriptor.check_availability`, `BackendRegistry.names`, `BackendRegistry.descriptor` | mitigate | Store descriptors and factories only; use top-level `importlib.util.find_spec(dependency.package)` in availability; tests prove listing/descriptor/availability do not call factories and registry module imports no CUDA/native packages. |
| T-03-02 | Spoofing / Tampering | `BackendRegistry.register` | mitigate | Reject duplicate descriptor names with `ValueError("Backend ... is already registered")`; tests cover duplicate rejection. |
| T-03-03 | Tampering | `BackendDependency`, `AvailabilityResult`, `BackendDescriptor` | mitigate | Use frozen/slotted dataclasses, tuples, and `MappingProxyType(dict(...))`; tests assert parameter mappings cannot be assigned through the public descriptor. |
| T-03-04 | Repudiation / Information Integrity | `AvailabilityResult` diagnostics | mitigate | Return `available`, `missing_requirements`, `diagnostics`, and `install_hints`; tests cover missing package diagnostics and deterministic always-available result. |
| T-03-SC | Tampering | npm/pip/cargo installs | accept | No package-manager install tasks exist in this plan; Phase 3 research Package Legitimacy Audit says no external packages are installed. |
</threat_model>
